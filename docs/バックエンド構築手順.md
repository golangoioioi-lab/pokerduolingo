# バックエンド構築手順（Cloudflare + Google ログイン + Stripe）

> **通常は `npm run setup` で自動化されています（[公開手順.md](公開手順.md)）。** この文書は、自動セットアップが途中で失敗したときの手動手順の参考です。


所要時間: 40〜60分。費用: Cloudflare・Google は無料枠、Stripe はテストモードなので 0 円。

アカウントの作成と秘密鍵の扱いを含むため、**オーナー自身が行う**手順です。
Stripe の秘密鍵（`sk_…`、`whsec_…`）は、チャットにもリポジトリのファイルにも書かないでください。コマンドで直接 Cloudflare に登録します。

コマンドはすべて `C:\\Users\\space\\Desktop\\holdem-lab-app` で実行します。

---

## 0. まずローカルで試す（アカウント不要）

```bash
npm run db:migrate:local
```
```bash
npm run db:seed:local
```

プロジェクト直下に `.dev.vars` を作り、`DEV_LOGIN=1` と書きます（作成済み）。そのうえで次を実行します。

```bash
npm run cf:dev
```

http://localhost:8788 で、Cloudflare と同じ仕組みで動きます。Google の設定がなくても、開発用のログインで動作を確認できます。

---

## 1. Cloudflare

1. https://dash.cloudflare.com でアカウントを作成
2. ターミナルでログイン（ブラウザが開きます）
   ```bash
   npx wrangler login
   ```
3. データベースを作成
   ```bash
   npx wrangler d1 create holdem-lab
   ```
   表示された `database_id` を `wrangler.toml` の `database_id` に貼る（公開して問題ない値です）
4. テーブルとレッスン本文を反映
   ```bash
   npm run db:migrate
   ```
   ```bash
   npm run db:seed
   ```
5. 初回デプロイ（Pages のプロジェクトが作られます）
   ```bash
   npm run deploy
   ```
   表示された URL（例: `https://holdem-lab.pages.dev`）を控えます。独自ドメインは後から設定できます
6. `wrangler.toml` の `APP_ORIGIN` をその URL に変更

## 2. Google ログイン

1. https://console.cloud.google.com で新しいプロジェクトを作成
2. 「API とサービス」→「OAuth 同意画面」: アプリ名・サポートメールを入力し、対象は「外部」
3. 「認証情報」→「認証情報を作成」→「OAuth クライアント ID」→ 種類「ウェブ アプリケーション」
   - 承認済みの JavaScript 生成元: `https://holdem-lab.pages.dev`（手順 1-5 の URL）と `http://localhost:8788`
4. 表示された **クライアント ID**（`…apps.googleusercontent.com`、公開してよい値）を2か所に設定
   - `wrangler.toml` の `GOOGLE_CLIENT_ID`
   - `.env.production.local` の `VITE_GOOGLE_CLIENT_ID`

## 3. Stripe（テストモード）

1. https://stripe.com でアカウントを作成。右上が **テストモード** になっていることを確認
2. 本番の申請前に、サポートへ事業内容を書面で確認（docs/決済・ホスティング検討.md の1章）
3. 商品を作成: 「Holdem Lab Pro」、継続の価格を月額・年額の2つ。それぞれの **価格 ID**（`price_…`）を控える
4. 秘密の値を Cloudflare に登録（1つずつ聞かれるので貼り付け）
   ```bash
   npx wrangler pages secret put STRIPE_SECRET_KEY
   ```
   ```bash
   npx wrangler pages secret put STRIPE_PRICE_MONTHLY
   ```
   ```bash
   npx wrangler pages secret put STRIPE_PRICE_YEARLY
   ```
5. Webhook を登録: 開発者 → Webhook → エンドポイントを追加
   - URL: `https://holdem-lab.pages.dev/api/billing/webhook`
   - イベント: `checkout.session.completed`、`customer.subscription.created`、`customer.subscription.updated`、`customer.subscription.deleted`
   - 表示された署名シークレット（`whsec_…`）を登録
   ```bash
   npx wrangler pages secret put STRIPE_WEBHOOK_SECRET
   ```
6. カスタマーポータルを有効化: 設定 → Billing → カスタマーポータル（解約・カード変更をオン）

## 4. 本番ビルドと公開

`.env.production.local` に次を書きます（すべて公開してよい値）。

```
VITE_BACKEND=cloudflare
VITE_GOOGLE_CLIENT_ID=…apps.googleusercontent.com
VITE_BUNDLE_PRO_CONTENT=false
VITE_PRICE_MONTHLY_JPY=980
VITE_PRICE_YEARLY_JPY=7800
```

```bash
npm run deploy
```

（価格は例です。Stripe で作った価格と同じ金額にしてください）

## 5. 動作確認

1. マイページ → アカウント →「Google で続ける」でログイン
2. Pro にアップグレード → 確認画面 →「上記に同意して申し込む」→ Stripe のテスト画面で、テスト用カード `4242 4242 4242 4242`（有効期限は未来の日付、CVC は任意の3桁）
3. アプリに戻って数秒で Pro になること（中級・上級の Pro レッスンが開ける）
4. プラン →「プランを管理」→ 解約 → 期間の終わりまで Pro が残ること
5. アカウント → 退会 → ログアウトされること

## 6. 公開前にやること

- Cloudflare の「セキュリティ」→「WAF」→「レート制限ルール」で `/api/*` に制限をかける（例: 同じ IP から 1分 60 回まで）
- Stripe を本番モードに切り替え、本番の鍵・価格 ID・Webhook シークレットで手順 3-4、3-5 をやり直す
- 特定商取引法の表記の [ ] を埋める

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| Google のボタンが出ない | `VITE_GOOGLE_CLIENT_ID` を入れて再ビルドしたか。Google 側の「承認済みの JavaScript 生成元」に今の URL があるか |
| ログインで「失敗しました」 | `wrangler.toml` の `GOOGLE_CLIENT_ID` がブラウザ側と同じ値か |
| 購入しても Pro にならない | Stripe の Webhook 画面で配信結果を確認。400 なら署名シークレット、500 なら `npx wrangler pages deployment tail` でログを確認 |
| 書き込み系で 403 | `APP_ORIGIN` が開いている URL と一致しているか |
