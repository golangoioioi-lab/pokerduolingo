## 1. 目的と前提

| 項目 | 内容 |
|---|---|
| 目的 | ポーカー戦略を「解説 → 練習 → 復習」の流れで身につけるアプリ |
| 主な利用者 | ポーカーを始めたばかりの人〜中級者。スマホで隙間時間に使う |
| 提供形態 | まず PWA（ブラウザでアプリのように動く Web アプリ）。後から Capacitor で iOS / Android アプリ化 |

| 収益 | フリーミアム（無料で基礎を学べ、有料プランで全コースと練習が無制限） |

### 前提として決めたこと（変更可）

- 「回収のしやすさ」は **収益の回収（課金の仕組みと、課金につながる導線）** と解釈した
- 当面は Web（PWA）のみ。iOS / Android 版は見送り
- バックエンドは Cloudflare（Pages + D1）、ログインは Google のみ、Web 決済は Stripe。アカウント作成と鍵の発行はオーナーが行う
- 価格は未定。本書では `[月額 ○○円]` のように仮置き

## 3. 画面構成

iOS 標準のタブバー構成。各タブの中は「大きなタイトル → 階層を進む → スワイプで戻る」という iOS の作法に従う。

```
タブ1 学ぶ
  ├ ホーム（続きから / コース一覧）
  ├ コース詳細（レッスン一覧）
  └ レッスン（全画面・ステップ式・クイズ付き）→ 完了画面
タブ2 練習
  ├ 練習ホーム（スポット選択・今日の残り問数）
  └ 練習セッション（テーブル → 回答 → 結果と解説）
タブ3 ツール
  ├ レンジ表（閲覧 / 編集）
  └ 勝率計算
タブ4 マイページ
  ├ 成績（正解率・スポット別・苦手ハンド）
  ├ プラン（Pro の案内・購入・管理）
  ├ 設定（外観：自動/ライト/ダーク、データのリセット）
  └ アカウント（ログイン / ログアウト / 退会）、利用規約、プライバシーポリシー、特定商取引法に基づく表記
```

課金画面（ペイウォール）はモーダルで出す。出すのは次の3か所だけにする。
- Pro コースのレッスンを開いたとき
- 練習の無料枠を使い切ったとき
- マイページの「プラン」

## 4. デザインシステム

- **基準**: Apple Human Interface Guidelines。部品は Ionic の iOS モードを使う
- **色**: iOS のシステムカラーに合わせる
  - 背景: grouped background（ライト `#F2F2F7` / ダーク `#000000`）
  - セル: ライト `#FFFFFF` / ダーク `#1C1C1E`
  - アクセント: ブルー（ライト `#007AFF` / ダーク `#0A84FF`）
- **ダークモード**: 端末設定に追従するのが標準。設定画面で手動切替も可能。保存先は端末内
- **文字**: システムフォント（SF Pro / ヒラギノ）。見出しは Large Title 34pt、本文 17pt
- **レイアウト**: inset grouped list（角丸のグループ化リスト）を基本にする。ノッチ・ホームバーのセーフエリアに対応
- **アクション色**: レイズ = 赤 / コール = 緑 / フォールド = 青（システムカラー）。色だけに頼らず文字ラベルも付ける
- **操作**: タップ領域 44pt 以上。正解・不正解時に触覚フィードバック（ネイティブ版のみ）
- **使わないもの**: 絵文字アイコン、グラデーション背景、装飾だけの影

## 5. 技術スタック

| 層 | 採用 | 理由 |
|---|---|---|
| UI | Ionic React 9（iOS モード） | iOS 純正に近い部品とダークモード |
| 言語・描画 | React 19 + TypeScript | |
| ビルド | Vite 8 | |
| ホスティング | **Cloudflare Pages** | 無料枠で商用利用可。静的ファイルと API を同じドメインで配信 |
| API | **Cloudflare Pages Functions + Hono** | `/api/*` を Workers 上で処理。Hono は Workers 向けの軽量ルーター |
| データベース | **Cloudflare D1**（SQLite） | Workers から直接使える。ブラウザからは直接触れない |
| 認証 | **Google ログインのみ**（Google Identity Services） | パスワードもメール送信も不要。ID トークンをサーバーで検証 |
| 決済（Web） | Stripe Checkout + Customer Portal + Webhook | カード情報を持たない。解約・カード変更は Stripe の画面 |
| テスト | Vitest。API は wrangler の `getPlatformProxy` で本物のローカル D1 に対して実行 | |
| PWA | vite-plugin-pwa | |

Supabase は 2026-11-16 に廃止した（契約先を Cloudflare と Stripe の2社に絞るため）。

## 6. アーキテクチャ

```
[ブラウザ]  ─ 同一オリジン ─  [Cloudflare Pages]
  React/Ionic                    ├ 静的ファイル（dist/）＋ _headers（CSP など）
  services/backend.ts  ── fetch ─┤ functions/api/[[path]].ts → server/app.ts（Hono）
                                 │     ├ auth.ts     Google ID トークン検証・セッション
                                 │     ├ billing.ts  Stripe（fetch + Web Crypto）
                                 │     └ D1（users / sessions / entitlements / progress / attempts / lesson_content）
                                 └──── Webhook ← Stripe
```

### デモモード
`VITE_BACKEND` が `cloudflare` でないビルドは、サーバーを一切使わないデモモードで動く。データは端末内、Pro は設定画面の切り替えで試せる。

## 7. 認証とアカウント

- ログイン方法は **Google アカウントのみ**。ログインなしでも無料範囲はすべて使える
- 流れ: Google のボタン → ID トークン → `POST /api/auth/google` → サーバーが署名・発行元・宛先（自分のクライアント ID）・有効期限・メール確認済みを検証 → セッションを発行
- セッション: 32 バイトの乱数トークンを Cookie `__Host-hl_session`（HttpOnly / Secure / SameSite=Lax / 30日）で渡す。DB にはトークンの SHA-256 だけを保存
- ログアウトでサーバー側のセッションも削除。退会は Stripe を先に解約してから全データを削除
- ローカル検証用に `/api/auth/dev` があるが、`DEV_LOGIN=1` かつ localhost からのアクセスの両方を満たす時だけ動く（本番では 404）

## 8. 課金設計

### プラン
月額・年額の自動更新サブスクリプション。価格は `VITE_PRICE_*_JPY`（表示用）と Stripe の価格 ID（請求用）で設定する。

### 購入の流れ
1. 課金画面でプランを選ぶ → **申込み内容の確認画面**（特定商取引法 12条の6 の表示事項）→「上記に同意して申し込む」
2. `POST /api/billing/checkout` → Stripe Checkout の URL
3. Stripe の画面で支払い（カード情報はこちらを通らない）
4. Stripe → `POST /api/billing/webhook`（署名検証・重複イベントは無視）→ `entitlements` を更新
5. アプリは `/api/me` を読み直して Pro を反映

**Pro かどうかの正は常に D1 の `entitlements`。** ブラウザの表示や戻り URL だけで Pro にしない。

### 解約・支払い方法の変更・領収書
Stripe Customer Portal（`POST /api/billing/portal`）。

### 回収のための設計
- 無料でも初心者・初級を最後まで学べる。ペイウォールでは増えるものを具体的に示す
- 指標: 1レッスン完了率、7日継続率、無料枠を使い切る割合、ペイウォール→購入率、月次解約率

## 9. セキュリティ

| リスク | 対策 |
|---|---|
| 有料コンテンツの抜き取り | 本番ビルドは Pro 本文を含まない（`VITE_BUNDLE_PRO_CONTENT=false`、ビルド結果で確認）。本文は `/api/lessons/:id` が有効な Pro 権限を確認してから返す |
| 権限の偽装 | `entitlements` を書き換えるのは Webhook だけ。Webhook は Stripe の署名で認証。ユーザー向け API に権限を書き換える経路はない |
| セッションの盗用 | HttpOnly・Secure・SameSite=Lax の Cookie。DB はハッシュのみ保存 |
| CSRF | 書き込み系の API は `Origin` ヘッダーが自分のオリジンと一致しないと 403 |
| XSS | レッスンは型付きブロックで描画（生 HTML を使わない）。CSP で自分のオリジンと Google のログイン以外のスクリプトを禁止 |
| SQL インジェクション | すべてプレースホルダ付きのクエリ。入力は形式チェック（レッスン ID の文字種など） |
| 秘密鍵の漏えい | Stripe の秘密鍵は `wrangler pages secret` にのみ置く。クライアントに渡すのは Google のクライアント ID だけ |
| 不正なリクエストの連打 | Cloudflare のレート制限ルールで `/api/*` を制限する（公開時に設定） |

上記は `server/api.test.ts`（18項目）で自動テストしている。

## 17. Cloudflare への移行（2026-11-16）

- Supabase（認証・Postgres・Edge Functions）を廃止し、Cloudflare Pages Functions（Hono）＋ D1 に置き換えた
- ログインは Google のみ。メール送信サービスは不要になった
- API の自動テスト 18 項目（ログイン、CSRF、Pro 限定レッスン、Webhook の署名・重複、退会）を本物のローカル D1 で実行
- ローカルの Cloudflare ランタイム（`wrangler pages dev`）で、未ログイン→401、無料ユーザー→403、Pro→本文取得、セキュリティヘッダー付与を確認
- 未確認: 本物の Google ログイン（クライアント ID 発行後）、Stripe との実際の購入（アカウント作成後）
